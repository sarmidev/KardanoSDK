# Dependency Provenance — Independent Checksum Comparison

Dated **2026-08-23**. This page compares selected build artifacts to
**publisher-provided** checksums or to bytes downloaded from the
publisher URL. Gradle's `origin="Generated by Gradle"` rows in
`gradle/verification-metadata.xml` record what Gradle hashed during
resolution. Those generated rows are **not** treated as proof of
origin. Enforcement still uses the SHA-256 metadata file; a tamper
test is recorded only as enforcement evidence.

Windows-classified artifacts are not in this record. Prompt 7 owns
Windows runner support.

## Method

1. Read the SHA-256 value from `gradle/verification-metadata.xml`.
2. Fetch the publisher URL (or the publisher `.sha256` / `.sha1`
   sidecar when that sidecar exists).
3. Compare. A match is recorded as **match**. A missing sidecar is
   recorded as **hash-of-download** (bytes from the publisher URL,
   compared to metadata).

User-Agent for fetches: `kardano-provenance`.

## What this does not prove

- A matching checksum does not prove the publisher is the original
  author, only that the bytes fetched from that URL match the recorded
  digest.
- Plugin/buildscript artifacts that Gradle does not lock still appear
  in verification metadata when they were resolved during generation.
- Tamper test (not committed): flipping the first nibble of the
  `junit-4.13.2.jar` SHA-256 in metadata makes
  `:core:compileTestKotlinJvm` fail with `Dependency verification
  failed`. That shows enforcement, not origin.
