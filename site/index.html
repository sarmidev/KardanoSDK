Apache-2.0 · Kotlin Multiplatform

Open-source Kotlin Multiplatform infrastructure for native Cardano mobile apps.

Kardano SDK keeps shared Cardano logic in Kotlin for Android, iOS, and JVM/Desktop, so a native mobile app can demonstrate a bounded, test-only Cardano wallet and transaction flow without a WebView bridge or duplicated platform business logic.

Status: Phase 1 MVP for a test-only, preprod transaction flow. Experimental, not independently reviewed, and not for mainnet funds or user-supplied private keys.

Open-source license for the SDK source. See the repository LICENSE.

Testnet/preprod, ADA-only

The demonstrated transaction flow is bounded to a public test fixture, Blockfrost preprod, and ADA-only drafts — not a general-purpose or mainnet wallet.

The problem

Cardano has strong web/TypeScript tooling, Rust low-level libraries, and web-first dApp connectors. There is no clearly dominant mobile-first, Kotlin Multiplatform-first SDK for teams building native Android and iOS apps that need to share the same Cardano business logic.

The approach

Kardano SDK shares Cardano wallet, provider, and transaction logic in Kotlin across Android, iOS, and JVM/Desktop, instead of duplicating platform-specific business logic or wrapping a web dApp in a WebView bridge.

What works today

  • UI-free core primitives, bounded hex/Bech32/CBOR handling, and structural CIP-19 address parsing.
  • Icarus/CIP-3 test-wallet restoration and CIP-1852 address generation.
  • Provider-neutral UTxO, protocol-parameter, and submit boundaries.
  • In-memory demo data plus Blockfrost preprod query and submission providers.
  • ADA-only transaction draft building, scoped local signing, and preprod submission from the test fixture.
  • Android-first Playground demo with shared Android/iOS/JVM/Desktop UI code.

Try the Playground

The default mock mode is the quickest way to see the guided flow without a network key. From the repository root: 

./gradlew :desktopApp:run

Mock mode uses deterministic ADA-only sample UTxOs so the Wallet, Funds, Build, and Sign steps complete without a network request; mock submission reports that it does not submit to a network. Live Blockfrost mode is preprod-only and requires an operator-supplied project id.

This is a developer demo you run from source. It does not imply a published package or a general integration API — see the Quickstart for Android/iOS run instructions, and the repository source for everything else.

Current limits

Experimental, test-only, preprod scope. This is not a mainnet product and not independently reviewed.

  • Not implemented Mainnet support.
  • Not implemented Arbitrary or user-supplied wallet import.
  • Not implemented General-purpose transaction signing.
  • Not implemented Native-asset (multi-asset) transactions.
  • Not implemented Plutus scripts, staking, metadata, or multisig.
  • Not implemented Hardware-wallet support.
  • Not validated iOS and JVM/Desktop compile as shared targets; Phase 1 runtime validation is Android-primary.
